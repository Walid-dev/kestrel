# The fifth live eval: Ask's drawings, one per kind (2026-11-23)

Every case from `evals/blocks/cases.json`, once per model, through the real model door (`node evals/blocks/run.ts
--live --model both --md`). A made-up Learn page and each question go through Ask's own prompt, with the catalog's
seven kinds in it (`src/shared/blocks.ts`), and the conversation client, with the app's budget (6,000 tokens,
thinking on). The scorer reads the drawings in the answer: the kind the subject has (a process as a flow, versions as
a timeline, numbers as a chart, kinds of a thing as a tree, a test as a check, a danger as a warning), each one that
reads, at most two, and none for a question that needs none.

**15 of 18 runs pass on the final prompt.** Qwen (careful): 7 of 9. Ornith (fast, Ask's default): 8 of 9.

How the prompt got there:

1. The first catalog: 12 of 18 (Qwen 7, Ornith 5). Neither drew a tree for the kinds of databases (a list); Ornith
   drew the versions of HTTP and a test question as flows, and gave its warning in plain words; Qwen drew three
   drawings for the versions. Two of the misses were the descriptions overlapping: "steps in order" fits dates too.
2. Each kind's line says what sets it apart from its neighbours (a flow is not dates; a timeline is anything by date
   or version; a tree replaces a list of kinds; a check's answer is never written in the text; a warning goes in a
   callout), and the prompt says to pick the one kind that fits best, in place of a list or a table. Ornith's
   timeline and check then passed. Its tree came back as good JSON with the closing fence at the end of the JSON's
   last line, which both parsers missed: they now accept it (and the page no longer swallows the words after it).
3. The final run: 15 of 18. Left: the versions of HTTP (Ornith: no timeline; Qwen: a comparison whose columns didn't
   read, so the reader now takes `name` or `label` for a column's title), and Qwen once drew three drawings. One
   run per case: the next runs say whether these hold.
