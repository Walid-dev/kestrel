# v1.0 · Searches on its own — the plan

**Status: planned (2026-11-25).** kestrel runs every search with what it owns. Until then the old setup runs the
searches and kestrel shows them.

## Why

kestrel still reaches into the old setup (`~/tools/hunts`) for its searches:

- it runs the old collectors from the old folder;
- it relies on the old engine to start the agent's Chrome;
- it mirrors the old database;
- it starts the old engine's Search now and reads its Live.

My rule (2026-11-25): no cross-repo dependency in the end state. Each bridge above is temporary and goes at the
cutover.

The chair hunt moved to kestrel on 2026-11-23 and back to the old setup on 2026-11-25, for two weeks. Each kestrel
round took about 5 minutes for 20 searches, against 10 to 13 for the old engine's 18. The run itself was fine. Three
gaps made it fragile:

- **A closed window breaks every search.** When the agent's Chrome had no window, its profile was unloaded, so
  every connection failed. kestrel said "isn't running" and couldn't recover. (The old engine opens a window since
  2026-11-25; kestrel names the cause but can't open one.)
- **Facebook isn't paced.** The old engine waits 30 to 60 s between Facebook searches; kestrel runs them back to
  back.
- **Live is blank during a search.** It shows no steps.

## What kestrel must own

1. **The agent's browser, in the engine (generic, no site names).**
   - Starting it: the app, the profile and the flags come from settings.
   - Keeping a window: a page target must exist, and one is opened when none does.
   - One search tab, and never a second browser.
   - Waits and caps per site, as data in the data folder: Facebook 30 to 60 s between searches; LinkedIn 8 page
     loads a run and 24 a day on my account.
   - A login pause, with one ping, when a site asks for a login again.
2. **Its own collectors, in its data folder (personal and site-fragile: never in the public repo).**
   - Kijiji, Facebook Marketplace, and LinkedIn signed in.
   - The job readers: company boards (Greenhouse, Lever, Ashby), Eluta, Built In, Job Bank, Remote OK, We Work
     Remotely, Hacker News, Wellfound, LinkedIn's public pages, and the job-alert emails through the gmail command.
   - Ported from the old engine and owned from then on: kestrel's own copies with their own packages, never a path
     into `~/tools/hunts`.
3. **The job engine's rules, in `src/domain/search` (generic, tested on made-up data).**
   - Every title in every place.
   - Each site's own turn, each search back to its last visit, pages while the jobs are new.
   - Filters, duplicates, the score, the left-out rules, and the model's read of the good ones.
4. **Live and Search now:** each search's steps as sentences, and Search now locked while a search runs (both
   built 2026-11-25 for kestrel's own runs).
5. **Pings:** a great find through ntfy, one per round, as the old engine does.

## The cutover, per hunt

1. kestrel's version runs Quiet beside the old one for three days. Each round, compare the finds per site, the
   duplicates and the time.
2. The old hunt goes Paused and kestrel's goes On. Two quiet weeks follow.
3. A final import. Then the bridges go:
   - the mirror (`mirror-v1.json`);
   - Search now through the old server;
   - Live's reads of the old Live;
   - the old collectors and the old timer.

## Rejected

- Keeping the old engine as kestrel's back end (my rule).
- Site scrapers in the public repo (2026-11-21: personal and site-fragile).
- A second browser for kestrel: one agent's Chrome, one search tab.
