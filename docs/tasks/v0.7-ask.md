# v0.7 · Ask on every page — the design and the build plan

**Status: step 1 built (2026-11-22).** The shared Ask runs on Learn's lessons and the quiz's questions, and a quiz is
kept as I take it. Step 2 starts on a GO.

## What it is

Every app gets the same Ask: a box at the foot of the page where I talk with the computer's model about what the page
shows. The model sees the page: the lesson, the question with my answer, and later the listings, the note, the tasks.
It keeps the conversation, so I can leave and come back to it. Over time it acts in the app: it finds, filters, adds
and marks. Any change waits for my tap.

## How it works

- **One box, one look.** The same component on every page (`web/src/ask.tsx`): the conversation so far, a few first
  questions to tap, and a line to ask. The answer streams in as the model writes it, in Markdown drawn with the
  lessons' own marks: bold, `code`, lists, code in colour, tables, and a link to a lesson that opens it.
- **One conversation per page.** It is kept in the database (`ask_messages`), by app and by what is open there: a
  lesson's id, or a quiz's id and the question's place. Start over clears it.
- **Each app writes its page for the model.** A helper per app (`HELPERS` in `src/domain/ask/ask.ts`) gives what the
  page is, its title and link, and its content in words. The page is context, never a limit: a question beyond it is
  answered from what the model knows.
- **The computer's own model.** One model use, Ask, on the Models page (the fast one by default: the eval in
  `docs/eval/2026-11-22-ask.md`). One answer at a time per page. Every call is recorded (Cost), every answer shows on
  Live. Nothing leaves the computer.
- **How the answer reaches the page.** The question returns at once; the answer grows in its row while the model
  writes, and the page reads the conversation again three times a second until it lands. Leaving the page loses
  nothing: the answer lands anyway. A restart marks an answer left half-written as failed.

## Actions: the model doing things (step 2 onward)

Each app gives the model a few actions of its own:

- **Reading actions** run at once, and their result goes back into the answer: find the listings that match, list
  the lessons due, read a note.
- **Changing actions** come back as a card under the answer that says in words what it would do. They run only when
  I tap the card: move a job to a stage, add a task, start a quiz on these lessons. Never on their own.
- **How the model asks for one** is decided by an eval first, on both local models: the door's tool calls, or a fenced
  action block in the answer that the page turns into the card. Either way, an action's arguments go through the
  app's own zod shape and its own domain function, the same path as the page's buttons.

## The apps, in order

| App            | What its page shows the model                                       | What it could do                                                 |
| -------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------- |
| Learn          | the open lesson, the pack's map                                     | link the lesson that covers it (built); start a quiz on a lesson |
| Quiz           | the question, the lesson's answer, mine, the mark, the explanation  | ask me the question another way (built); add it to review        |
| Searches       | the filters in view, the listings shown (title, pay, scores, stage) | find and filter in words, open one, set a stage, deep check      |
| Notes          | the open document, my notes                                         | find in the document, note some words, propose a change          |
| Tasks          | the open tasks                                                      | add, edit, tick, assign                                          |
| Research       | the report and its sources                                          | a follow-up, a deeper run                                        |
| Writing        | the open try, the job                                               | shorter, another tone, rewrite one paragraph                     |
| Applications   | the applications by state                                           | why one stopped, retry it                                        |
| Interview prep | the open answer-pack                                                | practise a question with me                                      |

## The steps

1. **The shared Ask, on lessons and quiz questions** (built 2026-11-22).
   - **Kept quizzes.** Migration 020 adds `quizzes`: the questions, my answers and marks, and my place. Routes under
     `/api/learn/quizzes`. The quiz page lists the quizzes I started, and `/quiz/<id>` comes back to my place. A
     question opens again from the score.
   - **Ask.** Migration 021 adds `ask_messages`, and Learn's `learn-ask` pick carries over to `ask`. The routes
     `/api/ask` (read, ask, start over). `chatModel` shares the client's one streaming request with `callModel`.
     Learn's one-question Ask is gone.
   - **Checks.** The domain's tests (`ask.test.ts`, `quiz.test.ts`). The Ask eval (`evals/learn`) now runs on Ask's
     prompt: the stand-in in the check, both models live for the record.
2. **Actions, on Searches.** First the actions eval: tool calls against a fenced block, on both models. Then find and
   filter (reading), then a stage and a deep check (cards to tap).
3. **Each other app**, in the table's order. Its helper and its actions, one app per step, each with its domain test.

## Out of scope

Cloud models: Ask stays on the computer's models. An Ask that reads other apps' pages: each Ask sees its own page,
and a general Ask on Home is a later decision. Speaking a question: later, with the interview helper's ears.
